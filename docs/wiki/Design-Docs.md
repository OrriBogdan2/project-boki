# Design docs

Design documents live in `docs/`. Documents for work that isn't built yet live on the **`design`
branch** (read them with `git show design:docs/<file>`), so `main` only carries docs that describe the
game as it is or the reference data behind it. When a design doc and the code disagree, the code
wins; later sections of a doc (dated) override earlier ones.

## On the design branch only

| Doc | What it covers |
|---|---|
| `docs/ROADMAP.md` | The plan for everything but controller support: real multiplayer, the meta loop and economy (the Exchange for materials, a separate Boki market), maps, onboarding, audio, telemetry, collectible Boki (editions, trading, crossover), rolling 30-minute raids and late joiners, the build order, risks and open decisions |
| `docs/ARCHITECTURE_PLAN.md` | Moving to a server-authoritative game (clients send inputs only), what stays open source vs a private backend (accounts, ownership, trading), phased plan, the asset license proposal |
| `docs/POSITIONING.md` | How the game is framed: pillars, scarcity and limited editions, words to use and avoid, look and feel, a checklist for any new feature or screen. Read before writing anything player-facing |
| `docs/TONE_AND_THREATS.md` | What we take from ARC Raiders (a world that wants you dead, the Blight) and Palworld (Boki that do things), and the build order |

The design branch also carries older copies of `ARCHETYPES.md` and `DASHES_AND_ABILITY_FEEL.md`; the
versions on `main` are newer.

## On main

| Doc | What it covers |
|---|---|
| `docs/ARCHETYPES.md` | The classes (it opens with the first six): who gives what, key layout, run levels, sockets and infusion, the merge vs R. Its "Kit loops" and "Kits2" sections at the end describe the built kits and win where they differ |
| `docs/DASHES_AND_ABILITY_FEEL.md` | A distinct dash per class and per class + Boki pairing; the feel pass; the global feel spec |
| `docs/KIN_GRAMMAR.md` | The Boki ability grammar: deliveries, effects, modifiers, triggers, budgets, the validator. Read before adding a Boki |
| `docs/BOKI_IDENTITY.md` | What makes every Boki its own: ids, inborn rolls, provenance |
| `docs/ABILITIES.md` | Every ability by slot, generated by `tools/gen_abilities_doc.py` |
| `docs/DEATH_AND_REVIVE.md` | The down, death, revive and respawn flow (SUPERVIVE's rules tuned for extraction) |
| `docs/EXPEDITION_SPEC.md` | Early estimate-based spec for the expedition (map scale, pacing) |
| `docs/MOVEMENT_FEEL.md` | Movement targets with sources, checked by `--move-feel-check` |
| `docs/KINFALL_CLASSES.md` | The original weight-class and weapon numbers (v1) |
| `docs/UI_DESIGN.md` | How menus look and the `ui.gd` helpers |
| `docs/SUPERVIVE_DATA.md`, `docs/SUPERVIVE_FEEL.md`, `docs/WEAPON_FIRING_DATA.md` | Reference data gathered from public sources (wiki, patch notes, measured footage). Nothing from game files |
| `docs/ASSET_CREDITS.md` | Third-party assets and their licenses |
| `docs/HANDOFF_farmstart.md` | Hand-off notes for the farm-start branch |
| `CONTENT.md` | How to add Boki, abilities, weapons and other content as JSON |

The handcrafted map's format is documented at the top of `tools/make_hollowcrown.py` on the `handmap`
branch (and `tools/make_skyreach.py` for Skyreach).
